| --------------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `analyze(conn, live_summary=None)`                  | Builds global analytics from cached trace rows.                      | Returns `metrics`, `anomalies`, `diagnosis`; also deletes/reinserts rows in `anomalies`.                             | Computes noisy SPs, incomplete runs, skipped step gaps, coverage, slow gaps, rare paths, broken instrumentation, and error handlers. This is global, not filter-scoped.                                                                 |

Expected path comes from `procedure_metadata.steps_json`. Actual rows come from `actual_run_events` for selected runs or `trace_events` for filters.                        |
| `learned_transitions(conn, name, type_name)`        | Learns frequent step-to-step transitions from historical trace rows. | Returns list of `{node, next_node, count}`.                                                                          | Uses SQL window function over `name/type/execution_query`, optionally scoped by name/type.                                                                                                                                              |

| `parse_exec_params(query)`                          | Regex parser for `@Param = value` SQL fragments.                     | Returns dict of parsed parameters.                                                                                   | Supports simple quoted and unquoted values. Used only for parameter intelligence and run signatures.                                                                                                                                    |
| `normal_step(value)`                                | Normalizes step text for fuzzy comparison.                           | Returns lowercased, whitespace-collapsed string.                                                                     | Used in text-based expected-vs-actual fallback matching.                                                                                                                                                                                |
| `readable_node_label(node)`                         | Converts technical node IDs/table/SP names into display labels.      | Returns cleaned label.                                                                                               | Removes prefixes like `dbo.`, `XStudio_`, `XMES_`, suffixes like `_Usp`, and underscores.                                                                                                                                               |
| `meaningful_table_name(value)`                      | Filters out useless table/entity names.                              | Returns boolean.                                                                                                     | Rejects generic names such as `dbo`, `cur`, `api`, `batch`, `table`.                                                                                                                                                                    |

## Material Issues | Significant Issues as of 23-05-2026

| Severity   | Area                        | Issue                                                                                                                                                            | Why it matters                                                                                                                                                  | Recommended fix                                                                                                                                                         |
| ---------- | --------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| High       | Expected path consistency   | `playback_payload()` compares against `procedure_metadata.steps_json`, but `expected_path_payload()` and `analyze_run_delta()` compare against `expected_paths`. | Same run can show different missing/unexpected results depending on whether UI uses playback, run detail, or saved delta. This is the biggest correctness risk. | Pick one canonical expected-path source. Prefer one function like `load_expected_steps(conn, name)` used by playback, expected-path graph, and run-delta analysis.      |
| High       | Run delta accuracy          | `analyze_run_delta()` returns score `1.0` when no expected rows exist.                                                                                           | A run with no expected path can look perfect instead of “expected path unavailable.” This recreates the fake-success class of bug.                              | If no expected rows, return `expected_unavailable=True`, `score=None`, and do not treat missing/unexpected as zero-success.                                             |
| High       | Selected-run playback       | `playback_payload()` applies `LIMIT` even for selected `run_id`.                                                                                                 | Long selected runs can be truncated before comparison, causing false missing/unexpected results.                                                                | For `run_id`, ignore UI limit or use a high safe cap after fetching run event count. Selected run should compare the whole run.                                         |
| High       | Run reconstruction grouping | `reconstruct_and_save_runs()` groups by `(name, type, execution_query)` and only splits by 5-minute gap.                                                         | Repeated executions with the same query inside 5 minutes can be merged into one fake run. Blank `execution_query` rows are especially vulnerable.               | Use stronger boundaries: Entered/Completed markers, SrNo/SubSeqNo reset, ID/time ordering, transaction/session key if available, or a configurable max gap per SP/type. |
| High       | Null step handling          | `_finalize_run()` does `e.get("step", "").lower()`. If `step` exists but is `NULL`, this raises.                                                                 | One null step can break run reconstruction.                                                                                                                     | Use `str(e.get("step") or "").lower()`.                                                                                                                                 |
| High       | Timestamp parsing           | `_finalize_run()` and `reconstruct_and_save_runs()` parse timestamps with `"%Y-%m-%d %H:%M:%S.%f"`.                                                              | If SQLite stores timestamps without fractional seconds, run reconstruction fails.                                                                               | Add a tolerant parser supporting both `%Y-%m-%d %H:%M:%S.%f` and `%Y-%m-%d %H:%M:%S`.                                                                                   |
| Medium     | Run list filtering          | `get_runs()` uses `start_time >= start` and `end_time <= end`.                                                                                                   | Runs overlapping the selected window can be hidden if they start before `From` or end after `To`.                                                               | Use overlap logic: `start_time <= end AND end_time >= start`.                                                                                                           |
| Medium     | Playback matching           | Expected-vs-actual key matching uses exact `(sr_no, sub_seq_no)`.                                                                                                | If expected has `sub_seq_no = NULL` but actual has `sub_seq_no = 1`, the same logical SrNo can be reported missing/unexpected.                                  | Normalize matching: match by `(sr_no, sub_seq_no)` when both exist; fall back to `sr_no` or normalized step text when one side lacks sub-sequence.                      |
| Medium     | Graph completeness          | `graph_payload()` adds `calls` edges to called procedures but does not create placeholder nodes for called procedures missing from metadata/traces.              | Some call edges silently disappear in the frontend because the target node does not exist.                                                                      | Add placeholder `unknown/procedure` nodes for called SPs not already present.                                                                                           |
| Medium     | Default focus               | `graph_payload()` picks dominant node purely by trace volume, including unknown/anonymous nodes.                                                                 | Default focus can land on noise rather than the most useful real SP.                                                                                            | Prefer dominant known procedure; fall back to unknown/anonymous only if no known procedure exists.                                                                      |
| Medium     | Playback search scope       | In `playback_payload()`, `q` searches only `step` and `execution_query`.                                                                                         | UI “Search Evidence” may appear inconsistent if normal event filtering searches details too.                                                                    | Include `details` if that column exists in `trace_events`, or keep the UI wording limited to step/query.                                                                |
| Medium     | Run delta persistence       | `reconstruct_and_save_runs()` commits runs/events before computing and inserting `run_deltas`.                                                                   | If delta computation fails, events are already assigned and future reconstruction will not create missing deltas.                                               | Compute deltas inside the same transaction before final commit, or add a repair path that backfills missing `run_deltas`.                                               |
| Medium     | Diagnostic reliability      | `analyze()` incomplete-run detection groups by `(name, type, execution_query)` across the whole cache, not actual reconstructed run boundaries.                  | It can flag incomplete workflows globally even when specific selected runs are fine.                                                                            | Prefer reconstructed `actual_runs.status` for run-level diagnosis; keep this as fallback/global heuristic only.                                                         |
| Medium     | Diagnostic false positives  | `analyze()` step gap logic assumes SubSeqNo should be contiguous between min and max.                                                                            | If gaps are intentional or conditional branches skip sub-sequences, it reports false damage.                                                                    | Compare against expected path per SP instead of numeric continuity alone.                                                                                               |
| Low-medium | Performance scaling         | `reconstruct_and_save_runs()` builds `events_for_run` using a nested set comprehension per run.                                                                  | Fine for small cache, but expensive as trace volume grows.                                                                                                      | Build `run_id -> event_ids` once, then map events by ID.                                                                                                                |
| Low-medium | Transition query scaling    | `learned_transitions()` scans all matching historical rows with a window function.                                                                               | Fine at 12k rows; could become slow as cache grows.                                                                                                             | Add time/limit constraints or supporting indexes if cache grows large.                                                                                                  |
